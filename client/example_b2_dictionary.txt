# GPU stage 1 / CPU stage 2 starting points, updated 2026-10-11.
# Target: similar elapsed time for the same number of curves on an RTX 5070
# and Ryzen 7 9800X3D with 12 stage-2 workers, mostly ~250-digit inputs.
# Every B2 is GMP-ECM's *effective* B2: stage 2 always runs to the end of its
# last whole block, past the requested B2, but GMP prints (and the client
# reports) the requested value. Each entry is that block end for the bound we
# chose, so the reported B2 is the tested B2. Requesting it gives the same GMP
# stage-2 layout, time and memory as the original round bound (verified
# 2026-10-11 with GMP-ECM 7.0.7). To change a bound, use GMP's effective value;
# see B2_TUNING.md.
# At 2.9e9 / B2=20e12: 8 workers used ~60 GiB resident; 12 exceeded 76.7 GiB
# of WSL RAM. The reduced bound is untested; keep k automatic and allow for RAM.
# Small bounds use the service minimum rounded up to GMP's block end, even
# where CPU stage 2 takes longer.
# Format: B1 B2. Deliberately omit k; GMP's automatic k reproduces each layout.
# Use --b2-dictionary example_b2_dictionary.txt. The measured bounds through
# 850e6 used 12 workers; the completed 2.9e9 run used 8. Choose workers to fit RAM.
# A few extra seconds of stage 2 at small B1 are acceptable.
# Without a factor, the service requires B2 >= 100 * B1 to complete a residue;
# every entry meets that threshold. See the notes for faster local-only bounds.
# Original example contributed by Oliver. Thanks Oliver!
